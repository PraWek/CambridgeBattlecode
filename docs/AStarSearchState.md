# AStarSearchState

`AStarSearchState` — это память незавершённого поиска пути A*. Он позволяет распределить поиск на несколько ходов, 
сохраняя уже проделанную работу. Класс объявлен в [bots/rc/navigation.py](../bots/rc/navigation.py).

Состояние используют функции поиска:

- `a_star_to_any` — ищет путь от одной стартовой клетки до любой из заданных целей,
  учитывая стоимость шагов и предпочтительные клетки. Используется, например, для движения к цели или возвращения к ядру.
- `a_star_from_any` — ищет кратчайший путь от любой из заданных стартовых клеток до любой из целей.
  Подходит для планирования конвейеров, когда возможны несколько точек начала маршрута.
- `a_star_from_any_with_bridges` — ищет маршрут между наборами стартовых и целевых клеток с возможностью переходов по мостам,
  учитывая стоимость обычных шагов, новых мостов и возможность использования существующих мостов.

Все три функции принимают объект `AStarSearchState` через параметр `state`.

## Зачем он нужен

Функции поиска принимают `max_expansions` — ограничение количества обрабатываемых клеток за один вызов. 
Если лимит закончился, а путь ещё не найден, поиск возвращает управление боту.

Без сохранённого состояния следующий вызов начал бы всё сначала и мог бы снова упереться в тот же лимит. 
`AStarSearchState` сохраняет промежуточные данные, чтобы следующий вызов продолжил поиск с места остановки.

## Что хранится внутри

| Поле | Назначение |
| --- | --- |
| `query` | Определяет задачу поиска: старт, цели и другие параметры, включённые функцией поиска в ключ запроса. |
| `queue` | Очередь клеток, которые ещё предстоит обработать. |
| `g_score` | Лучшая найденная стоимость пути до каждой клетки. |
| `came_from` | Откуда пришли в клетку — для восстановления маршрута. В варианте с мостами также хранит признак перехода по новому мосту. |
| `sequence` | Счётчик для упорядочивания элементов с одинаковым приоритетом в вариантах поиска `a_star_from_any` и `a_star_from_any_with_bridges`. |
| `pending` | Показывает, что поиск остановлен по лимиту и требует продолжения. |

## Жизненный цикл

1. **Создание.** Бот создаёт объект состояния. Пока в нём нет данных о поиске.
2. **Начало поиска.** Бот передаёт объект в функцию поиска. По мере обработки клеток в нём накапливается прогресс:
   какие клетки ещё нужно проверить, как до них добраться и сколько стоит путь.
3. **Пауза.** Если лимит обработки клеток исчерпан, а поиск ещё не завершён, функция возвращает управление боту.
   Объект сохраняет прогресс между ходами, а `pending = True` сообщает, что поиск требует продолжения.
4. **Продолжение.** Бот снова вызывает функцию поиска с тем же объектом и той же задачей.
   Поиск продолжается с места остановки. Пауза и продолжение могут повторяться несколько ходов.
5. **Завершение.** Когда путь найден или все варианты исчерпаны, функция возвращает результат,
   а накопленные данные состояния очищаются и `pending` становится `False`. Тот же объект можно использовать для нового поиска.

Продолжение не запускается автоматически: бот должен снова вызвать функцию поиска и передать тот же объект состояния.
Если каждый раз создавать новый объект, прогресс между вызовами не сохранится.

Если изменились старт или цели, при следующем вызове прежний прогресс сбрасывается и поиск начинается заново.
Такой же сброс происходит при изменении других настроек, которые конкретная функция использует для распознавания задачи поиска.
При отмене плана бот может очистить сохранённое состояние, чтобы отказаться от незавершённого поиска.

## Как используется

Пример использования:

```python
search_state = self.a_star_state("revisitable_target")

path = a_star_to_any(
    None,
    current,
    {target},
    lambda _controller,
    pos: self.is_roadable_position(pos),
    self.tile_cache.neighbor,
    movement_directions=DIRECTIONS,
    max_expansions=_SUPPLY_SEARCH_EXPANSIONS,
    state=search_state,
)

if search_state.pending:
    return False  # Поиск ещё не завершён.

# Дальше бот обрабатывает результат поиска и выбирает действие.
```

Боты получают и сохраняют search_state между ходами через метод `BaseBot.a_star_state(name)` ([bots/rc/base.py](../bots/rc/base.py)).

Разные имена позволяют хранить отдельные поиски, например путь к цели (`"revisitable_target"`) и 
путь обратно к ядру (`"return_to_core"`). Один объект состояния обслуживает одну задачу поиска в каждый момент времени.

## Как понимать результат

Пустой `path` сам по себе не означает, что пути нет:

| Результат `a_star_to_any` | Значение |
| --- | --- |
| `path == []`, `pending == True` | Поиск ещё идёт: достигнут лимит обработки клеток. |
| `path == []`, `pending == False` | Поиск завершён без маршрута либо маршрут не требуется: бот уже в цели или набор целей пуст. |
| Непустой `path`, `pending == False` | Путь найден. Он содержит клетки после старта, включая выбранную цель. |

У варианта с мостами при незавершённом поиске или отсутствии маршрута возвращается `None`; различить эти случаи также помогает `pending`.

Готовый маршрут возвращается вызывающему коду. Сам `AStarSearchState` после завершения его не хранит: это состояние вычисления, а не кеш готовых путей.
